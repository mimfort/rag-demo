# Протокол HTTP

## Общее описание

HTTP (HyperText Transfer Protocol) — протокол прикладного уровня для передачи
гипертекстовых документов. Работает по модели «запрос-ответ»: клиент посылает
запрос, сервер возвращает ответ. Протокол текстовый (до HTTP/2) и не хранит
состояние между запросами — это называется stateless.

## Методы запроса

GET запрашивает ресурс и не должен изменять состояние сервера (свойство
идемпотентности и безопасности). POST отправляет данные для создания нового
ресурса или произвольной операции. PUT заменяет ресурс целиком, PATCH — частично
изменяет, DELETE удаляет. HEAD аналогичен GET, но возвращает только заголовки,
без тела ответа. OPTIONS показывает разрешённые методы для ресурса и
используется в CORS preflight-запросах.

## Коды ответа

Коды делятся на пять классов по первой цифре. 1xx — информационные,
встречаются редко (101 Switching Protocols при апгрейде до WebSocket).
2xx — успех: 200 OK, 201 Created, 204 No Content. 3xx — редиректы:
301 Moved Permanently, 302 Found, 304 Not Modified. 4xx — ошибки клиента:
400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found,
429 Too Many Requests. 5xx — ошибки сервера: 500 Internal Server Error,
502 Bad Gateway, 503 Service Unavailable, 504 Gateway Timeout.

## Заголовки

Заголовки несут метаинформацию о запросе или ответе. Content-Type указывает
MIME-тип тела (application/json, text/html, multipart/form-data).
Authorization передаёт учётные данные, чаще всего в формате
`Bearer <token>` или `Basic <base64>`. Accept говорит серверу, какие форматы
готов принять клиент. Cache-Control управляет кешированием.
Cookie и Set-Cookie реализуют сессии поверх stateless-протокола.

## HTTPS и TLS

HTTPS — это HTTP поверх TLS. TLS обеспечивает три свойства: шифрование
(данные нельзя прочитать в пути), целостность (нельзя подменить незаметно)
и аутентификацию сервера (через сертификат). Установка соединения включает
TLS-хэндшейк: обмен случайными числами, проверка сертификата, согласование
симметричного ключа сессии.

## REST

REST (Representational State Transfer) — архитектурный стиль, а не протокол.
Ключевые принципы: ресурсо-ориентированные URL, использование HTTP-методов по
семантике (GET читает, POST создаёт), stateless-взаимодействие, единообразный
интерфейс. На практике большинство «REST API» — это JSON over HTTP с разной
степенью строгости следования принципам.

## WebSocket

WebSocket — отдельный протокол для двунаправленного соединения. Начинается с
обычного HTTP-запроса с заголовком Upgrade: websocket, после успешного
ответа 101 соединение переходит в режим WebSocket. После этого сервер и
клиент могут слать друг другу сообщения в любой момент, не дожидаясь
запроса. Используется в чатах, биржевых тикерах, играх.
