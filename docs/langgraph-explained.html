00 — ОРИЕНТИРЫ

Две библиотеки, а не одна

LangChain и LangGraph — разные инструменты от одних авторов. Их легко путать, но роли у них чёткие.

⬡ LangChain

Кирпичики

Единый язык общения с LLM: модель, сообщения, инструменты, парсеры. Это словарь для разговора с моделью.

⬢ LangGraph

Сценарий

Поверх LangChain. Описывает управляющую логику агента как граф и крутит цикл «думай → действуй». Это режиссёр, который двигает кирпичики.

Аналогия для программиста. LangChain — это функции и типы данных. LangGraph — это while-цикл со state, который эти функции вызывает в нужном порядке.
01 — КИРПИЧИКИ LANGCHAIN

Сообщения, модель, инструменты

Вся переписка с моделью — это не строки, а список объектов-сообщений. У тебя в коде встречаются четыре типа:

SystemMessageИнструкция модели — твой системный промпт «Ты помощник СКК Рондо…»
HumanMessageВопрос пользователя
AIMessageОтвет модели. Внутри либо текст .content, либо просьба вызвать инструмент .tool_calls
ToolMessageРезультат выполнения инструмента — кладётся обратно в историю

Модель — единый интерфейс

Твоя модель крутится локально в LM Studio. Но раз она «OpenAI-совместимая», LangChain позволяет подключить её той же обёрткой ChatOpenAI — меняется только base_url. Остальной код не знает, что это не настоящий OpenAI.

agent/llm.py
return ChatOpenAI(
    model=rag_settings.chat_model,
    base_url=rag_settings.lm_studio_base_url,  # ← вся «магия» подмены
    api_key=rag_settings.lm_studio_api_key,
    temperature=0.2,  # стабильный tool-calling, не креатив
    max_retries=1,
)

Инструменты — функция превращается в tool

Декоратор @tool делает из обычной функции инструмент. Самое неочевидное: LangChain автоматически читает имя, типы аргументов и docstring — и превращает их в JSON-описание для модели.

agent/tools.py
@tool
async def get_weather(date: str) -> dict:
    """Получить прогноз погоды на дату в формате YYYY-MM-DD.
    Возвращает {date, temperature_c, condition, sunny, raw} либо {error}."""
    ...
💡 Docstring — это не комментарий, а инструкция для модели. Модель читает именно его, чтобы понять, когда и как звать инструмент. Поэтому он у тебя такой подробный — by design.

bind_tools — «прикрепить» инструменты к модели

После bind_tools модель при каждом вызове видит описания инструментов и может вместо текста вернуть tool_calls — структурированную просьбу «вызови get_weather с date="2026-06-01"».

⚠️ Модель сама инструмент не выполняет. Она только просит. Выполняет код (узел tools). Это ключевое разделение — запомни его для следующей секции.
02 — ИЗ ЧЕГО СОСТОИТ ГРАФ

State, узлы, рёбра

LangGraph держится на трёх понятиях. Разберём каждое на твоём agent/graph.py.

① State — общая память, которая течёт через граф

agent/state.py
class AgentState(TypedDict):
    messages: Annotated[list[BaseMessage], add_messages]

State — словарь, который проходит через весь граф. У тебя одно поле — messages (вся история). Магия в add_messages: это reducer — правило обновления. Когда узел возвращает {"messages": [новое]}, список дописывается, а не заменяется.

🧩 Без этого reducer'а каждый узел стирал бы историю. Именно поэтому узлы возвращают список из одного сообщения, а в state их накапливается много.

② Узлы — функции, которые что-то делают

agent — зовёт LLM tools — выполняет инструменты

agent берёт messages, при нужде добавляет system-промпт в начало, вызывает модель, возвращает её ответ. tools — готовый узел ToolNode(TOOLS): смотрит на tool_calls в последнем ответе, сам вызывает твои функции и кладёт результаты как ToolMessage. Диспетчер «если имя == get_weather…» писать не нужно.

③ Рёбра — куда идти дальше

agent/graph.py
graph.set_entry_point("agent")              # входим в agent
graph.add_conditional_edges("agent", tools_condition)  # РАЗВИЛКА
graph.add_edge("tools", "agent")          # ВСЕГДА назад в agent

tools_condition — готовая функция: смотрит на последний AIMessage и возвращает "tools" если есть tool_calls, иначе END (модель ответила текстом — выходим).

03 — ЖИВАЯ СХЕМА

ReAct-цикл в движении

Это и есть весь агент. Нажми «Запустить» — пройдём один реальный вопрос по шагам: «будет ли солнечно завтра и свободны ли корты?»

▸ Граф в покое. Жми «Вперёд ▶» — шаг за шагом. Слева увидишь, как сообщения накапливаются в state.messages, а на схеме подсветится активный узел.
state.messages — пусто
    узел agent активен узел tools активен не активен

    Паттерн «модель рассуждает → действует инструментом → смотрит результат → снова рассуждает» называется ReAct (Reasoning + Acting). LangGraph просто крутит его, пока модель не перестанет просить инструменты.

    04 — ПО ШАГАМ

    Тот же прогон текстом

    Вход. В граф передаётся {"messages": [HumanMessage("…будет ли солнечно и свободны ли корты?")]}
    Узел agent. Модель видит вопрос + описания инструментов, понимает что нужны данные → возвращает AIMessage с двумя tool_calls. Текста нет.
    Развилка. tools_condition видит tool_calls → направляет в tools.
    Узел tools. ToolNode выполняет обе твои async-функции, ходит по HTTP в skkrondo API, кладёт два ToolMessage с результатами в state.
    Ребро tools → agent. Безусловно возвращаемся к модели.
    Узел agent (снова). Теперь модель видит вопрос + результаты инструментов. Данных хватает → возвращает AIMessage с обычным текстом, без tool_calls.
    Развилка → END. tool_calls нет → граф завершён. Пользователь получает ответ.
    05 — ЗАПУСК И СТРИМИНГ

    Как граф крутится — runner.py

    graph.astream(..., stream_mode="updates") запускает граф и по мере выполнения отдаёт обновления — после каждого узла прилетает {имя_узла: что_добавлено_в_state}.

    agent/runner.py
    stream = graph.astream(
    {"messages": [HumanMessage(query)]},
    stream_mode="updates",
)
async for update in stream:        # {node_name: state_delta}
    ...                              # → SSE-события для фронта

    Твой _astream_events превращает эти обновления в события (tool_call, tool_result, final_answer), которые фронтенд показывает как timeline в реальном времени.

    Две инженерные детали в твоём коде

    ♻️ Singleton графа. Граф собирается один раз на процесс — build_graph() тяжёлый (биндинг инструментов). State в графе не хранится, он живёт внутри каждого astream-вызова, поэтому переиспользовать безопасно.
    🛑 MAX_ITER. Страховка от зацикливания: если модель будет бесконечно дёргать инструменты, цикл agent ⇄ tools оборвётся. Без лимита кривая логика модели могла бы крутиться вечно.
    ИТОГ ОДНОЙ ФРАЗОЙ

    Соберём всё вместе

    LangChain даёт модель, сообщения и инструменты. LangGraph связывает их в граф agent ⇄ tools со state-памятью и крутит ReAct-цикл, пока модель не выдаст финальный текстовый ответ.
