# Основы языка Python

## Что такое Python

Python — высокоуровневый интерпретируемый язык программирования с динамической
типизацией. Создан Гвидо ван Россумом, первый релиз состоялся в 1991 году.
Python используется в веб-разработке, машинном обучении, анализе данных,
системном администрировании и автоматизации.

## Типы данных

В Python есть встроенные неизменяемые (immutable) типы: int, float, str, tuple,
frozenset и bool. И изменяемые (mutable): list, dict, set, bytearray.
Неизменяемые объекты безопасно использовать как ключи словаря и элементы
множества — у них стабильный hash.

Числа в Python имеют произвольную точность: int может быть сколь угодно большим,
ограничения накладывает только память. Float — стандартный 64-битный double по
IEEE 754.

## Списки и словари

Список (list) — упорядоченная изменяемая последовательность. Доступ к элементу
по индексу за O(1), вставка в конец амортизированно за O(1), вставка в начало
или удаление из произвольной позиции — O(n).

Словарь (dict) — хэш-таблица. С Python 3.7 порядок вставки сохраняется.
Поиск, вставка и удаление по ключу в среднем O(1). Внутри dict использует
открытую адресацию и пробинг.

## Менеджеры контекста

Конструкция `with` управляет ресурсами: открыл — поработал — гарантированно
закрыл, даже при исключении. Реализуется через методы `__enter__` и `__exit__`.
Типичный пример — работа с файлом: `with open("file") as f: ...` гарантирует,
что файл закроется, что бы ни случилось внутри блока.

## Виртуальное окружение

venv (или virtualenv) изолирует зависимости проекта от системного Python.
Внутри окружения свой `pip` и свои установленные пакеты. Это позволяет
держать разные версии одной и той же библиотеки для разных проектов.
Создаётся командой `python -m venv .venv`, активируется через
`source .venv/bin/activate` на Unix или `.venv\Scripts\activate` на Windows.

## GIL — Global Interpreter Lock

GIL — это мьютекс в интерпретаторе CPython, который позволяет только одному
потоку исполнять байт-код Python в каждый момент времени. Из-за GIL потоки
не дают ускорения на CPU-bound задачах, но прекрасно работают для I/O-bound:
пока один поток ждёт сеть или диск, другой может работать. Для настоящего
параллелизма используют multiprocessing (отдельные процессы со своим GIL)
или asyncio (кооперативная многозадачность в одном потоке).
