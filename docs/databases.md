# Базы данных

## Реляционные базы данных

Реляционная модель основана на отношениях (таблицах) с фиксированной схемой:
у каждой таблицы заданы колонки с типами, а строки представляют записи.
Связи между таблицами выражаются через внешние ключи. Самые популярные
реляционные СУБД — PostgreSQL, MySQL, SQLite, Oracle, Microsoft SQL Server.

PostgreSQL отличается богатой системой типов (JSONB, массивы, диапазоны,
геометрические типы), поддержкой расширений (PostGIS для геоданных, pgvector
для векторного поиска), оконными функциями, CTE и продвинутым планировщиком
запросов.

## Индексы

Индекс — это вспомогательная структура данных, ускоряющая поиск. Самый частый
тип — B-tree: сбалансированное дерево, дающее логарифмический поиск по
точному значению, диапазону и по сортированному порядку. Hash-индекс работает
только для равенства, GIN индексирует «многие значения в одной строке»
(массивы, JSONB, полнотекстовый поиск). GiST — обобщённый индекс для
произвольных типов с операторами «пересечения».

Индекс ускоряет SELECT, но замедляет INSERT/UPDATE/DELETE (его тоже надо
обновлять) и занимает место на диске. Поэтому индексы создают точечно — под
конкретные запросы, которые видно в EXPLAIN.

## Транзакции и ACID

ACID — четыре свойства транзакций: Atomicity (всё или ничего),
Consistency (БД переходит из одного валидного состояния в другое),
Isolation (параллельные транзакции не мешают друг другу), Durability (закоммиченные
данные не теряются при сбое).

Уровни изоляции в порядке усиления: Read Uncommitted (можно прочитать
незакоммиченные данные другой транзакции — «грязное чтение»),
Read Committed (только закоммиченные, но один и тот же SELECT в одной
транзакции может вернуть разное — «неповторяющееся чтение»),
Repeatable Read (одинаковые SELECT возвращают одно и то же, но возможны
«фантомные строки»), Serializable (полная сериализуемость, как будто
транзакции исполнялись по очереди).

## NoSQL

NoSQL — собирательное название для не-реляционных хранилищ. Документные
(MongoDB) хранят JSON-подобные документы со свободной схемой. Ключ-значение
(Redis, DynamoDB) дают быстрый доступ по ключу. Колоночные (Cassandra,
ClickHouse) оптимизированы под аналитические запросы по столбцам. Графовые
(Neo4j) хранят узлы и связи.

Выбор между SQL и NoSQL — это компромисс. Реляционные дают строгую
согласованность, мощный язык запросов и зрелую экосистему. NoSQL обычно
масштабируется горизонтально проще, но за счёт ослабления гарантий
(BASE вместо ACID) и потери выразительности запросов.

## Векторный поиск

Векторный поиск — это поиск по семантической близости, а не по точному
совпадению ключевых слов. Тексты, картинки или аудио сначала превращаются
в вектора фиксированной размерности (эмбеддинги) с помощью нейросети.
Векторы располагаются в многомерном пространстве так, что близкие по смыслу
объекты оказываются рядом.

Поиск сводится к задаче «найти k ближайших соседей» (kNN). Точные алгоритмы
работают за O(N) — перебор всех векторов. Приближённые (ANN — Approximate
Nearest Neighbors) — например, HNSW (Hierarchical Navigable Small World) или
IVF (Inverted File Index) — дают логарифмическое время за счёт небольшой
потери точности.

PostgreSQL поддерживает векторный поиск через расширение pgvector. Оно
добавляет тип данных vector и операторы расстояния: <-> (евклидово),
<#> (отрицательное скалярное произведение), <=> (cosine distance). Можно
создавать индексы HNSW или IVFFlat по выбранной метрике.
